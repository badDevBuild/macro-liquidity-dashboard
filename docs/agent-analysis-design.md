# Agent 晨间分析：生产落地设计

## 结论

Agent 应该负责理解不同数据放在一起意味着什么；脚本继续负责取数、单位换算、公开公式和质量检查。两者不能互相替代。

每天的正式顺序是：

1. 07:30 数据脚本获取官方数据并写入历史库。
2. 数据质量门禁生成一份不可修改的正式快照。
3. 数据脚本再收集过去 24 小时新闻和未来 90 天官方事件，保留原文、URL、时间和哈希。
4. 只有快照允许分析时，Agent 才读取这份快照、历史和已绑定的新闻事件包。
5. Codex 使用当前 ChatGPT 订阅登录生成结构化分析，不能修改原始数据。
6. 本轮输出 Schema 会把指标和新闻事件引用限制在当前快照实际存在的 ID 内。
7. 独立校验器逐项核对分析引用的指标、日期、当前值、区间变化和新闻事件编号。
8. 若校验失败，运行器先修复可证明无歧义的格式错误，再让 Agent 只修错误字段；全部校验通过后才显示在个人网页。

Agent 失败、超时或证据不匹配时，数据和走势图照常更新。页面明确写“今天的 Agent 分析未生成”，不会用固定规则拼一段假分析，也不会把旧分析冒充今天的分析。

## 谁负责什么

### 确定性程序

- 从官方或可信转发线路取数；
- 保存原始响应和 SQLite 历史；
- 处理单位、日期、修订和缺失值；
- 计算 `美联储总资产 - TGA - RRP`；
- 决定数据能否进入正式快照；
- 检查 Agent 引用的每个数字是否与快照完全一致。

### Agent

- 结合流动性参考值、准备金、实际利率、美元、NFCI 和短端融资条件；
- 区分主驱动、反向信号和暂时无法判断的部分；
- 说明这套组合对股票和加密意味着什么，但不输出买卖指令；
- 给出当天值得继续观察的触发条件；
- 逐条判断新闻事件是相关、待观察、可能已反映，还是无关；
- 对缺失、滞后和混合频率做明确说明。

## 第一版只用一个 Agent

第一版采用单 Agent，而不是多个 Agent 互相讨论。原因是输入只有一份正式快照，任务边界清楚；单 Agent 更容易追踪模型、输入、输出、延迟和订阅用量。只有在评估证明“研究”和“复核”确实需要分离时，再增加第二个审阅 Agent。

运行脚本先把正式快照、指定指标历史、来源日期和数据质量压缩成一份只读上下文，再一次性传给 Codex。Agent 在空白临时目录和只读沙箱里运行，提示词明确禁止调用工具或访问网络；它没有交易、发布或修改数据库的权限。

## 输出与证据契约

混合观察日期和频率的数据允许共同参与分析。Agent 应注明实际日期或比较区间；“今日判断”以及“不能称为当日净流出”等提醒均允许。校验器继续核对数值、日期和比较区间，不再通过“今天/今日/当日”关键词一票否决整篇分析。时间含义由 Agent 根据上下文解释。

Agent 必须按 [`config/agent-analysis.schema.json`](../config/agent-analysis.schema.json) 的 `1.5` 版契约输出。核心字段包括：

- 本轮快照编号和模型版本；
- 总体判断：偏松、偏紧、混合或无法判断；
- 置信度；
- 主要驱动和矛盾信号；
- 今天继续观察什么；
- 本轮新闻事件包编号、筛选说明和保留项；
- 未知项和数据质量说明；
- 每个关键结论引用的指标、日期、当前值和比较区间。

网页优先读取通过验证的 `data/analysis/latest.json`。如果它不存在，则读取通过同一套证据校验的 `data/analysis/shadow/latest.json`。分析文件的 `snapshot_run_id` 和 `context_bundle_id` 必须分别对应当前数据快照和已归档上下文包，否则不显示结论。

流动性参考值分成两个证据编号，避免把不同观察日期的数据混为一谈：

- `net_liquidity_proxy`：使用最新日频 TGA 和 RRP 配合最近一次联储周报，只允许引用 1 周变化；
- `net_liquidity_proxy_weekly`：三项都按联储周度日期对齐，用于 1 月、3 月和 1 年趋势判断。

## 运行与调度

生产关键路径使用常驻 Mac Studio 上的一次性 `codex exec` 任务，由数据脚本成功后触发。它复用当前 Codex 的 ChatGPT 订阅登录，不需要另外配置 OpenAI API Key。当前模型固定为 `gpt-5.6-sol`，推理强度固定为 `medium`。

数据和 Agent 共用现有 launchd 调度入口，但不是同一个故障域：

- 数据抓取成功且 `analysis_allowed=true` 时，才触发 Agent；
- Agent 超时、登录失效、模型失败或证据校验失败，不改变数据任务的成功结果；
- 相同正式快照默认只分析一次，锁文件阻止并发重复运行；
- 每次运行保存上下文、提示词、原始输出、逐次校验结果和最终状态，便于回看；
- 影子输出与生产输出分目录保存；网页只显示通过校验的当前分析。

时间预算为：数据任务 07:30 开始；正式快照生成后立即触发 Agent；每次模型调用最多 8 分钟，默认最多三次调用。第一次生成完整分析；若失败，后两次优先读取原稿和精确错误，只做小范围修复，不重新分析整篇。08:00 前无合格产物时，数据和图表照常更新；页面显示“今日分析未生成”，不会用旧文案替代。

恢复流程仍然保持失败关闭：本地程序只会自动拆分“每个拆分结果都恰好是本轮合法 ID”的粘连字符串，或去掉完全重复的合法 ID；任何需要猜测含义的改动都必须交给 Agent 定向修复。每次使用的动态 Schema、提示词、原始输出、自动修复动作和校验错误都写入当轮运行目录。

模型名称、推理强度、提示词版本和分析 schema 版本都必须写入产物。更换模型前先跑固定评估集，不允许静默切换模型。

手动命令：

```bash
# 默认是影子运行；当前快照已经成功分析过时会直接跳过
python3 scripts/run_agent_analysis.py --mode shadow

# 查看 14 个观察日和人工复核门禁
python3 scripts/check_agent_health.py --days 14

# 只有 Agent 门禁 hard_pass=true 时才可能写生产分析
python3 scripts/run_agent_analysis.py --mode publish
```

## 上线门槛

至少覆盖以下固定案例：

1. TGA 上升时，必须正确解释为按公式抽走参考值；
2. TGA 下降时，必须正确解释为支持参考值；
3. 参考值上升，但实际利率和美元同时上升时，结论必须是混合而非单边利好；
4. 核心数据缺失或过期时，必须降低置信度或拒绝分析；
5. RRP 下降不能直接写成资金进入股票或加密；
6. 日频与周频指标日期不同时，不能假装同步发生；
7. 引用数字被故意改动时，发布校验必须拦截。

先用历史快照回放，再连续影子运行 14 个不同观测日。自动门禁要求 14 天都成功且最终证据校验无误；随后还要人工逐日检查方向、语义、频率边界和风险表述，并在 [`config/agent-production-approval.json`](../config/agent-production-approval.json) 明确批准。两道门都通过后，`hard_pass` 才会变成 `true`，用于确认正式稳定状态。个人试用由 [`config/agent-dashboard-policy.json`](../config/agent-dashboard-policy.json) 单独控制，可以在积累稳定性样本的同时直接使用网页分析。
