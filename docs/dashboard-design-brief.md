# 宏观流动性看板设计 Brief

状态：`confirmed`，用户于 2026-08-28 确认进入代码实现。

## 1. Feature Summary

这是一个供项目所有者每天上午在手机上阅读的宏观流动性决策支持工具。它先给出当前流动性环境与主要驱动，再让用户逐层验证联储、财政、货币市场、利率、全球美元和风险资产传导数据。

## 2. Primary User Action

在一分钟内理解今天的环境、变化方向和主要驱动；发现重要或异常变化后，用一次操作进入指标详情并验证来源。

## 3. Design Direction

- **颜色策略：** 页面外壳采用 Restrained，使用带暖意的浅色中性背景和单一交互强调色；数据可视化使用四个低饱和度语义色区分四个宏观层级。
- **场景句：** 用户在早晨自然光或室内柔和光线下拿起手机，注意力清醒但时间有限，需要安静地确认市场环境而不是被行情氛围刺激。因此默认使用浅色主题，深色主题作为后续可选项。
- **锚点参考：** Apple Weather 的移动端信息节奏，Stripe Dashboard 的证据与状态表达，Financial Times Markets 的克制数据密度。
- **创意北星：** “晨间观测台”。它是一张结构清楚的观测桌，不是赌场屏幕，也不是交易终端复制品。
- **视觉方向探针：** `docs/design/probes/mobile-directions-v1.png`。探针中的数值仅用于构图，不是项目数据。

建议不是机械地三选一，而是统一视觉系统下的页面分工：

- 方向 A 作为默认总览，承担晨间结论、主要驱动和贡献关系；
- 方向 C 作为流动性传导页，承担联储到财政、货币市场和风险资产的因果结构；
- 方向 B 作为指标详情与数据健康页，承担高密度核验、观测日期和来源状态。

## 4. Scope

- 保真度：production-ready。
- 广度：完整看板表面，包括总览、指标详情、数据健康和晨报归档。
- 交互：可运行的响应式 Web/PWA，不是静态稿。
- 时间意图：持续打磨到可部署，并覆盖加载、降级、错误和离线状态。

## 5. Layout Strategy

手机首屏从上到下依次是：数据状态与更新时间、今日环境判断、三项主要驱动、四层流动性结构。不是把所有指标压成同尺寸卡片，而是使用一条主叙事轴：状态结论占据视觉起点，驱动贡献随后展开，指标按层级组织成可下钻的节奏。

桌面端增加同屏对比空间，但不改变阅读顺序。详情使用独立页面和行内展开，不把模态框作为默认交互。

## 6. Key States

- **正常：** 12 项核心指标通过门禁，显示最新状态与完整来源。
- **降级：** 缺少 1 至 2 项但仍允许分析，首屏明确列出缺失项和影响。
- **阻止分析：** 关键分组失效或发生跨源冲突，只展示已知事实和上一份正式快照。
- **加载：** 保留真实布局的骨架，不使用页面中央旋转图标。
- **离线：** 展示设备最后缓存的正式快照、缓存时间和离线说明。
- **空历史：** 新指标尚无足够历史时解释原因，不伪造趋势图。
- **长文本与大数值：** 标签换行、数字保持可读，不横向挤压关键状态。

## 7. Interaction Model

- 点击任一宏观层级进入对应驱动与时间序列。
- 点击指标进入独立详情页，查看 1 月、3 月、1 年和 5 年区间。
- 来源、观测日期和质量状态在详情页内直接展开。
- 手机端底部提供总览、传导、账本、数据四个稳定入口。
- 所有交互具备 hover、focus、active、disabled 和 loading 状态。

## 8. Content Requirements

需要短而具体的状态语言：正常、降级、阻止分析、使用缓存、数据过期、来源冲突。Agent 内容固定分为已验证事实、主要变化、驱动解释、条件性影响和未知事项。禁止使用“水来了就一定上涨”等确定性投资表达。

## 10. Confirmed Decisions

1. 方向 A 用于总览，方向 C 用于传导地图，方向 B 用于账本和数据健康。
2. 采用“晨间观测台”、浅色优先、Restrained 外壳加低饱和度数据色的方向。
3. 首版先把浅色主题和手机体验做到生产质量，深色主题后置。
4. 首版 Agent 晨报不伪造占位内容；先交付确定性数据、计算、缺失态和来源核验，待影子运行与分析契约稳定后再接入。
