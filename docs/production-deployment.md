# 生产部署与每日更新

## 参考生产架构

维护者的公开演示地址是 <https://shushu.host/liquidity/>。下面描述的是一种参考部署，不要求使用相同服务器、域名或操作系统。

Mac Studio 负责所有会变化的工作：

1. 北京时间每天 07:30 拉取官方或可信来源数据，包括核心宏观、稳定币、ETF、Coinbase现货溢价、衍生品、跨资产相对强弱、日元套息、WTI/Brent 油价与 EIA 周度石油供需指标。
2. 检查日期、单位、缺失、来源冲突和分组覆盖率。
3. 收集过去 24 小时的可信新闻，以及未来 90 天的官方重要事件。
4. 调用当前 Codex 订阅，固定使用 `gpt-5.6-sol` 和中等推理生成分析。
5. 核对 Agent 写出的数字、日期、指标编号和新闻引用。
6. 构建一个只含正式快照的生产包，上传到服务器。
7. 服务器原子切换到新版本，重启服务并检查公网页面与 API。

服务器不运行数据采集和 Agent，也没有 Codex 或 OpenAI 凭证。它只在 `127.0.0.1:8877` 提供只读服务，由 Nginx 暴露为 `/liquidity/`。

## 哪些失败不会让整个看板停掉

流动性参考值自 2026-09-09 使用每日 TGA/RRP 同日配对序列，联储保留周值；首屏各项最新变化合计仍保留混合周期。完整口径、补历史命令与回归要求见 [liquidity-proxy-methodology.md](liquidity-proxy-methodology.md)。每日 07:30 更新时刻不变。

- 少 1 至 2 条非关键数据，且分组门禁仍通过：发布，并在页面标明缺失。
- Agent 失败：发布新的数据和走势图，分析区明确显示本轮分析未完成。
- 新闻来源部分失败：保留能拿到的新闻和事件，并在数据状态里记录失败来源。
- 跨资产来源失败：优先使用已通过新鲜度检查的缓存；不可用时隐藏对应比较，不阻断核心宏观数据发布。
- 日元套息来源部分失败：只展示仍通过新鲜度检查的分项，并明确缺口；它不进入净流动性公式，也不阻断核心宏观数据发布。
- 油价或 EIA 周度数据部分失败：使用仍在新鲜度内的缓存；超过门槛后明确标记不可用，不补零，不阻断核心流动性发布。
- 关键数据不合格：不发布，公网继续保留上一份完整版本。
- 上传、服务启动或公网检查失败：自动回滚到上一版，并在 Mac Studio 发出失败通知。

服务器保留最近 7 个完整版本。每个版本都包含文件哈希、数据快照编号和 Agent 分析编号，可以核对网页到底在使用哪一轮数据。

## 常用检查

本机查看最近一次发布：

```bash
cat data/status/latest-public-deploy.json
```

手动重新发布当前已通过检查的快照：

```bash
python3 scripts/deploy_public_dashboard.py
```

只构建生产包，不上传：

```bash
python3 scripts/build_public_release.py --output /tmp/macro-liquidity-release
```

完整测试：

```bash
python3 -m unittest discover -s tests -v
```

## 安全边界

- 专用服务器账号是 `macroliq`，不能获得通用 root 权限。
- 它只被允许重启或停止 `macro-liquidity-dashboard.service`。
- 生产服务仅监听回环地址，公网只能经过现有 HTTPS Nginx。
- 发布包不包含本机 SSH 私钥、部署配置、原始抓取文件、日志、锁文件或 Codex 登录信息。
- 当前网页是公开地址，只能放公开市场数据。私人持仓与交易信息不得进入这个接口。
- 跨资产比值只表示相对强弱，不表示资金从一类资产流向另一类资产；收益率相关性也不用作因果或买卖信号。
- 日元套息模块把“套息动力”和“平仓压力”分开判断；CFTC 只覆盖报告期货，外汇掉期成交额不提供买卖方向，风险同步也不证明因果。

真实的 `config/production-deploy.json` 与 `known_hosts` 不进入 Git。先复制 `config/production-deploy.example.json`，填入自己的主机、密钥路径与 URL，再在部署机上保管。`deploy/server/patch_nginx_liquidity.py` 只会修改通过 `--config` 明确指定、且恰好包含一次 `--anchor` 的 Nginx 配置文件；运行前应先备份并人工审查。
